# Wire Protocol (v2 — Protobuf)

Both the Rust server and the Kotlin/libGDX client speak this protocol.

Schema: `proto/shootgame.proto` (proto3, no package).
Serialization: **Protocol Buffers**.
- Rust: `prost` (types generated by `build.rs` via `protoc-bin-vendored` — no system protoc needed).
- Kotlin: protobuf-java via the `com.google.protobuf` Gradle plugin.

## Framing

Every message is prefixed with a **1-byte type tag**, and TCP additionally
prefixes a **4-byte little-endian length** of `1 + body_size`:

```
TCP:  [ len:u32 LE ][ type:u8 ][ protobuf body ]
UDP:                [ type:u8 ][ protobuf body ]
```

- **TCP (54555)** — reliable: `Login`, `LoginResponse`, and client `State`/`Shoot` inputs.
- **UDP (54777)** — lossy: server broadcasts `PlayerState` and `PlayerHit`.

## Type tags

| Tag | Message | Direction / transport |
|----:|---------|-----------------------|
| 1 | LoginPacket | client → server (TCP) |
| 2 | LoginResponsePacket | server → client (TCP) |
| 3 | PlayerStatePacket | both (client→server TCP; server→client UDP) |
| 4 | PlayerShootPacket | client → server (TCP) |
| 5 | PlayerHitPacket | server → client (UDP) |
| 6 | PlayerConnectedPacket | server → client (TCP/UDP) |
| 7 | PlayerDisconnectedPacket | server → client (TCP/UDP) |
| 8 | (register) | client → server (UDP) body = raw u32 LE client id |

## UDP registration

The client must teach the server which UDP address to send state to. After
login, send a **UDP** datagram `[0x08][id:u32 LE]` to the server's UDP port.

## Reconnection

`LoginResponsePacket.session_token` is an opaque string. Persist it (e.g. in
`Gdx.app.getPreferences`) and send it back in `LoginPacket.session_token` to
resume the **same player id** (grace window ~120 s).
